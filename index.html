03 Independent project · In progress · Dry-run only

AI Campaign Decision Engine (ACDE)

An evidence-to-action system for marketing decisions. It takes structured evidence, produces a typed decision, routes work through specialist analysis, production and QA, and keeps consequential actions behind human approval.

The implementation includes deterministic routing, a versioned rulebook, an append-only execution ledger, and evaluation checks. Its latest verification includes 190 passing automated tests, 27 LLM shadow runs, and five human-adjudicated cases.

Current boundary: ACDE runs in dry-run mode. It does not publish campaigns, change ad spend, or mutate CRM records.

Reddit Social-Listening Agent

A social-listening agent that turns subreddit chatter into a daily, ranked digest of posts that contain buying signals — tool-seeking, churn and comparison language, budget talk — not mere chatter. Runs headless on a pay-per-call data layer (treg.to): one CLI call per subreddit watchlist entry, priced in cents.

Every digest commits its own real evidence to the repo: posts scanned, posts kept, filter rules, and the actual dollar cost of the run (first production run: 15 posts scanned, 10 kept, $0.0050). The filter design follows the signal-triage principle — a single soft hit is a breadcrumb, not demand.

Stack: Python CLI · treg.to pay-per-call APIs ($0.001/call) · zero-subscription data layer · markdown + JSON digests committed as proof.

System Pipeline · Reddit Buying-Signal Digest

STEP 01 Watchlist Subreddit list (marketing, SEO, Entrepreneurship…)
STEP 02 treg.to Fetch One pay-per-call route per subreddit — $0.001 each
STEP 03 Signal Scoring Lexical buying-signal markers + engagement floor
STEP 04 · GATE Stack & Rank Single soft hits stay out — signals must stack
OUTCOME Daily Digest Markdown + JSON, cost-of-run stamped, committed

How I work

01 Objective

01 · Understand the work

Start with the business objective, the people involved, and the current process.

02 Decompose

02 · Break down the workflow

Map the inputs, outputs, dependencies, repetitive steps, decision points, and failure cases.

03 Select

03 · Choose the simplest effective solution

Use existing automation, scripts, APIs, AI agents, or a hybrid approach. Avoid adding complexity without a clear reason.

04 Govern

04 · Build in controls

Use validation, QA, logs, stop conditions, and human approval wherever the risks justify them.

05 Iterate

05 · Measure and improve

Check whether the system works as intended, document what fails, and improve it using observed results rather than assumptions.
